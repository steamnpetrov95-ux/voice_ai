# Проверка в облачной среде

Целевой продукт — Windows-приложение. Текущая машина — Linux без физических аудиоустройств. Здесь можно проверить DSP, файлы, интерфейс и взаимодействие колбэков через тестовые устройства; фактический захват микрофона, VB-CABLE, Discord и Windows EXE требуют Windows.

В этой машине зависимости установлены в `/workspace/voice_ai/.venv`. PortAudio и libjack извлечены из пакетов Debian trixie в `/workspace/.local/audio-libs`. Пакеты получены через подписанный индекс официального репозитория Debian; проверка TLS и подписей не отключалась. Symlink `libportaudio.so` нужен, чтобы `ctypes.util.find_library` нашёл библиотеку вне системного каталога.

```bash
cd /workspace/voice_ai
export LD_LIBRARY_PATH=/workspace/.local/audio-libs/usr/lib/x86_64-linux-gnu${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}
export XDG_CACHE_HOME=/workspace/.cache
export VOICELAB_DATA_DIR=/workspace/voice_ai/.local/settings
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q
```

Для новой Linux-машины предпочтительна установка PortAudio штатным пакетным менеджером. Резервный способ без записи в `/usr` автоматизирован в `scripts/setup-cloud.sh`. Он предназначен только для Debian-подобной облачной машины, не для Windows-пользователя.

Список устройств в этой среде пуст; кнопка включения микрофона корректно отключена. Обработка аудиофайлов доступна. Результат тестов в этой машине не подтверждает работу физического аудиоустройства или Windows-сборки. CI для целевой ОС включает запуск обработчика уже собранного EXE.

Проверено: 85 тестов прошли, проверка неиспользуемых имён и импортов Ruff прошла, графический интерфейс запущен через настоящий Qt event loop с последующим штатным закрытием. Протестирована повторная установка через `setup-cloud.sh`. Отдельно проверены автоматический выбор виртуального выхода VB-CABLE, запрет подмены его обычными колонками, распознавание дополнительных CABLE-A/B и защита от обратной звуковой петли. Windows-скрипты и workflow подготовлены, но в этой Linux-среде не исполнялись.
