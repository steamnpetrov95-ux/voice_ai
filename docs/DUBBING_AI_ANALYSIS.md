# Что удалось установить по Dubbing AI 1.8.2

Дата анализа: 22 октября 2026 года. Цель — объяснить различие с npetrov VoiceLab на i7-2600, 8 ГБ RAM и GTX 1050 Ti 4 ГБ.

Изучен предоставленный пользователем [установщик из релиза forai](https://github.com/steamnpetrov95-ux/voice_ai/releases/tag/forai). На первом этапе EXE и его DLL не запускались. Выполнены распаковка Inno Setup, инвентаризация файлов, чтение заголовков PE и доступных строк. Чужие бинарники и данные голосов в исходники проекта не включены.

## Подтверждённые факты

Файл: `DubbingAI_v1.8.2_10151936_Release_C_Setup.exe`, 121 461 536 байт. SHA256:

```text
af7ea3aa9c743473d0cb927e9d388da192af64681870b3c2aedc11a7e987f231
```

Установщик распознаётся innoextract 1.9 как Inno Setup 6.1.0 Unicode. Распаковано 1302 файла приложения, суммарно 152 287 436 байт. Сам установщик — PE32; приложение и проверенный SDK — PE32+ x64.

В каталоге `vc_model` находятся **1244 файла**:

| Группа | Число файлов | Размер |
| --- | ---: | ---: |
| Небольшие файлы | 1241 | 2796–2924 байта каждый; суммарно 3 548 544 байта |
| Крупный файл `6f51031213cc38a90992b69e7ec433c4` | 1 | 14 508 608 байт |
| Крупный файл `dd9f3ba78e223d341fab75a7767b10a4` | 1 | 21 647 360 байт |
| Крупный файл `d136725af877d2b05083e4dd2867af71` | 1 | 34 346 176 байт |

Три крупных файла занимают суммарно **70 502 144 байта**. Все 1241 небольших файла содержат Base64 с бинарными данными. Внутренний формат не восстановлен; последующее испытание SDK подтвердило использование этих файлов как профилей голосов.

В составе есть нативные библиотеки `dubbing-sdk-windows.dll`, `dubbing-base.dll`, `dubbing-sdk-dsp.dll`, `libagora_audio_processing.dll`, `libsamplerate-0.dll`, `libspeexdsp.dll`. В доступных строках приложения присутствуют `groupModelId`, `binFileIds`, `localFileName`, `selectVoiceModel`, `setVoiceId`, `VCEngine transform`, проверки и загрузка файлов моделей. Есть проверки авторизации и обращения к серверным API.

В проверенных таблицах прямых импортов приложения и двух основных SDK-библиотек не найдены зависимости ONNX Runtime, CUDA, TensorRT или DirectML. Это **не исключает** статическую линковку, динамическую загрузку или загрузку дополнительных компонентов после установки. В SDK есть секция `.themida`; обычное чтение строк и экспортов не раскрывает устройство движка.

`assets.pak` — ZIP из 1703 зашифрованных ресурсов: 1514 PNG, 187 XML, один TTF и один JSON. По именам это ресурсы интерфейса. `csorigin.config`, несмотря на расширение, распознаётся как моно WAV PCM 48 кГц.

Есть отдельный виртуальный аудиодрайвер `DubbingAudio.sys`, INF и каталог подписи. В INF указано имя микрофона `Dubbing Microphone`, версия драйвера `04/18/2025,15.55.58.533`. Наличие своего драйвера объясняет отдельное устройство Windows, но не определяет скорость нейросинтеза.

## Интерпретация и её пределы

Сочетание небольшого числа крупных файлов, множества очень маленьких файлов и группировки моделей в клиенте **согласуется с общей моделью и небольшими профилями/параметрами голосов**. Поэтому большая библиотека голосов не обязательно означает отдельную полную нейросеть для каждого персонажа.

По установщику нельзя подтвердить точную архитектуру, размер вектора голоса, квантование, использование потокового кеша, реальный расход RAM/VRAM и скорость. Нельзя также установить, какие дополнительные модели клиент скачивает после запуска. Сетевые API и WebSocket сами по себе не доказывают обработку звука в облаке.

Размер файлов на диске не равен расходу памяти и не является измерением производительности. Графический клиент Dubbing AI не запускался; на указанном ПК он не профилировался. Результаты последующего запуска SDK приведены ниже.

## Что это означает для npetrov VoiceLab

У нас другой набор моделей: общие ContentVec v1 и RMVPE в полном профиле имеют размер около 293 и 362 МБ, дополнительно используется отдельная модель RVC выбранного актёра. Одновременно загружается один голос, а не вся библиотека. В лёгком профиле RMVPE не загружается.

В [измерении версии 0.2.2](https://github.com/steamnpetrov95-ux/voice_ai/releases/download/v0.2.2/neural-benchmark.json) на CPU Windows CI получены следующие результаты. Это не измерение пользовательского i7-2600 или GTX 1050 Ti.

| Показатель для блока 320 мс | Полный AI | Лёгкий AI |
| --- | ---: | ---: |
| Медиана обработки | 334,0 мс | 247,4 мс |
| P95 обработки | 353,9 мс | 275,8 мс |
| Пиковая рабочая память процесса | 1633,5 МиБ | 976,6 МиБ |
| Анализ речи | 71,8 мс | 44,1 мс |
| Определение высоты | 54,9 мс | 1,3 мс |
| Модель голоса | 15,8 мс | 10,0 мс |
| Декодер/нейросинтезатор | 189,2 мс | 190,2 мс |

В лёгком профиле декодер занимает около 77% общего времени обработки. Это наиболее значимая цель следующей оптимизации. Нейросети уже исполняются нативным ONNX Runtime; перенос одного интерфейса с Python/Qt на C++ не устраняет вычисления декодера.

Для существенного дальнейшего снижения нагрузки нужен более дешёвый нейросинтезатор либо другая компактная модель, рассчитанная на потоковую обработку и аппаратное ускорение целевого ПК. Совместимость с шестью существующими RVC-голосами и качество русской речи потребуется проверить отдельно. Увеличение аудиобуфера может улучшить устойчивость ценой задержки, но не заменяет такую оптимизацию.

Из предоставленного установщика не получена модель, которую можно просто импортировать в наш RVC ONNX-конвейер. Поддержка такого формата и производительность его движка не подтверждены.


## Динамическая проверка и слой совместимости 0.3.0

После статического анализа изучены вызовы незашифрованного клиента к публичному интерфейсу SDK. На Windows CI DLL загружались штатным Windows loader. Патчи защиты, авторизации, сетевые учётные данные и установка драйвера не применялись. Исходный клиент и его интерфейс не копируются; личный установщик включает предоставленные владельцем SDK и модели.

Восстановлена фабрика `?V_@IVoiceTranscribe@DUBBING@@SAPEAV12@XZ` и следующие смещения Win64 vtable:

| Смещение | Вызов |
| --- | --- |
| 0x08 | Инициализация: JSON общих файлов, JSON профилей, входная и выходная частоты |
| 0x10 | Уничтожение singleton (последующая фабрика не восстанавливает экземпляр) |
| 0x18 | Выбор профиля по int64 ID |
| 0x20 | Сброс потока |
| 0x28 | Включение преобразования |
| 0x60 | Преобразование моно PCM16 на месте, количество сэмплов int64 |

Успех инициализации и выбора голоса — код **10000**. Объекты общих файлов: `id`, `bid`, `localPath`; профилей: `id`, `binFileIds`, `localPath`. Для предоставленных файлов роли общих моделей:

1. `dd9f3ba78e223d341fab75a7767b10a4`
2. `d136725af877d2b05083e4dd2867af71`
3. `6f51031213cc38a90992b69e7ec433c4`

Неправильный порядок приводит к сбою SDK при выборе голоса. ID небольших профилей можно назначить при инициализации. Вызов преобразования ограничен порцией не более 160 мс, как в исходном клиенте. Буферы приложения 320/480/640 мс разбиваются на такие порции: большие прямые вызовы приводили к повреждению heap SDK. Это интерфейс конкретной версии 1.8.2, а не универсальная поддержка будущих SDK.

Первый изолированный тест реальной речи: блок 160 мс, медиана обработки **13,57 мс** на CPU Windows CI. Исходный и выходной звук различаются, результат ненулевой. Outbound-сеть процесса Python заблокирована Windows Firewall. Следовательно, для протестированного профиля обработка возможна локально без аккаунта и облачного синтеза. Полная матрица последующей проверки публикуется в `native-benchmark.json` вместе с установщиком.

Исходные названия персонажей получить не удалось: небольшие файлы не декодировались в читаемую JSON-метаинформацию, а анонимные публичные запросы вернули ноль совпадающих названий. Поэтому используются номера и пользовательские названия. Нет основания утверждать соответствие конкретного номера Железному Человеку, Локи или другому персонажу. После установки 0.3.0 пользователь сообщил, что работа стала лучше и интерфейс показывает около 72 мс. Это подтверждает запуск на его ПК; отдельного измерения сквозной задержки и оценки русского звучания по каждому профилю нет.

Реализован отдельный `NativeConverter`: проверка хешей SDK и моделей, один экземпляр движка на процесс, PCM16, переключение профилей в потоке обработки и сброс потока при остановке. Уничтожение singleton ломает следующий запуск, поэтому модели остаются в памяти до закрытия приложения. Собственные микрофонный тракт, интерфейс и VB-CABLE сохранены. SDK и данные голосов не хранятся в Git; личная сборка получает их из приложенного владельцем установщика.


## Повторная проверка названий после 0.3.0

22 октября 2026 года проверены фактические адреса ресурсов из клиента. На Windows публичные `a1/a2/a3.dubbing-ai.com/res.json` вернули список CDN `d1/d2/d6`. Файл `/rvc-client/assets/config.json` с доступных CDN содержит объявления `broadcast`, без списка голосов.

Доступен базовый API `https://console.dubbing-ai.com`: GET `/api/rvc/getGlobalInfo` вернул код 0 (`Successfully retrieved`). GET `/api/rvc/getAllSpeakers` и `/api/rvc/getAliasSpeakers` вернули код 7 (`Request ended`), пустой объект данных и ноль названий. POST к этим адресам вернул HTTP 404. По ответу кода 7 нельзя достоверно определить причину отказа. Аккаунты, токены и обход проверок не использовались.

Санитизированный результат — `public-native-catalog.json` рядом с предоставленным установщиком в релизе `forai`; воспроизводимая проверка — workflow `Inspect public native voice names`. В нём сохраняются только структура публичных ответов, коды, адреса ресурсов и поля каталога голосов.

Номера в VoiceLab назначены по сортировке имён файлов и не являются исходными ID Dubbing AI. Нельзя сопоставлять их с порядком карточек на скриншоте. Для автоматического восстановления нужен каталог, содержащий одновременно имя персонажа и ссылку/идентификатор соответствующего файла профиля. Наличие такого локального каталога в установленном Dubbing AI на ПК пользователя пока не подтверждено.
