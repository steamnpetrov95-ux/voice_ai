# npetrov VoiceLab для Windows

Локальная замена голоса с выводом в виртуальный микрофон Windows. В личной версии **0.3.2** подключён оригинальный нативный SDK из предоставленного владельцем установщика Dubbing AI 1.8.2. Это слой совместимости с его движком, а не независимо воссозданная нейросеть или полная копия приложения.

В комплекте **1241 профиль** и три общие модели. Обработка идёт на CPU; DirectML и большие RVC-модели для этого режима не нужны. Профили работают без интернета: это проверяется в Windows с заблокированной сетью. Наименования персонажей из установщика восстановить не удалось: профили обозначены номерами, выбранный голос можно переименовать. Соответствие конкретным героям и качество русского произношения нужно оценить прослушиванием.

Нативный голос можно менять во время работы микрофона. Каталог показывает по 40 карточек на страницу, поиск охватывает всю библиотеку. Есть выбор физического микрофона, виртуального выхода и наушников, галочка прослушивания и запись WAV. Для начала используйте буфер **80 мс**; при стабильном звуке можно попробовать **40 мс**, при прерываниях вернуться к **160 мс**. При обновлении прежнее значение сохраняется. Время обработки отображается внизу окна и не равно полной задержке. Измерения CPU Windows CI приложены к релизу в `native-benchmark.json` и `native-latency.json`; они не гарантируют такую же скорость на i7-2600 / GTX 1050 Ti.

Прежний RVC-режим сохранён для уже установленных или импортированных моделей. Шесть прежних моделей русских актёров не входят повторно в новый установщик. Их известные роли по-прежнему показаны в карточках и поиске. Нативные профили и RVC — разные форматы.

**Мультяшные стили**: кнопка «Мультяшные стили · без AI» открывает 12 быстрых образов — Бурундучок, Маленький помощник, Добрый великан, Гоблин-плут, Утёнок, Пришелец, Герой в броне, Тёмный страж, Мульт-робот, Лесная ведьма, Огр и Кукольный герой. Это стилизация, а не копии актёров. Модели и видеокарта не нужны. Быстрый сдвиг высоты читает 1–25 мс истории вместо фазового вокодера; звучание более зернистое. Полная задержка зависит также от аудиоустройств. Выход в виртуальный микрофон, прослушивание и запись работают как обычно. Перед переходом из работающего AI остановите микрофон.

**Режим эффектов** сохраняет высоту, эквализацию, робота, хорус, эхо и реверберацию. Его 60 карточек — рецепты DSP, а AI-каталог показывает только реально установленные нейросетевые модели.

## Запуск на Windows 10/11 x64

1. Скачайте **`VoiceLab-Setup.exe`** из [Releases](https://github.com/steamnpetrov95-ux/voice_ai/releases). Это один установщик; Python, исходники и команды не нужны. Релиз появляется после успешной сборки и проверки на Windows.
2. Запустите установщик. Нативные голоса устанавливаются вместе с приложением. Если виртуального микрофона ещё нет, оставьте опцию **«Установить виртуальный микрофон VB-CABLE»**. Он сам скачает официальный драйвер, проверит подпись издателя и запустит оригинальную программу установки VB-CABLE. Для этого шага нужны интернет и разрешение Windows на установку драйвера. Если драйвер уже установлен, этот шаг пропускается.
3. В окне VB-CABLE нажмите **Install Driver**. Если установщик запросит перезагрузку, перезагрузите Windows. Голосовой драйвер скачивается с сайта производителя, а не распространяется копией внутри npetrov VoiceLab.
4. Откройте npetrov VoiceLab. В режиме **«AI — замена голоса нейросетью»** выберите карточку голоса, физический микрофон и виртуальный выход, затем нажмите **«Включить микрофон»**. Дождитесь загрузки модели. В Windows и нужной программе выберите вход **CABLE Output**.
5. Чтобы услышать результат в реальном времени, выберите наушники и поставьте галочку **«Слышать себя в реальном времени»**. Её можно включать и выключать во время работы; виртуальный микрофон продолжит передавать голос. Для проверки без драйвера есть режим **«Только наушники — без драйвера»**.

Приложение устанавливается для текущего пользователя; права администратора запрашиваются только для установки драйвера. Настройки хранятся в `%APPDATA%\VoiceLab\settings.json`; записи сохраняются в выбранное вами место. Приложение не отправляет аудио в сеть. Индикатор «Живой сигнал» показывает обработанный звук.

Если установка драйвера не завершилась, нажмите **«Установить виртуальный микрофон»** в npetrov VoiceLab: скачивание и установка запускаются повторно. Ошибка сети, отмена запроса администратора или неподтверждённая подпись не удаляют уже установленное приложение. Существующие записи и настройки при удалении приложения сохраняются.

## Естественная замена голоса и ваш компьютер

Для ПК с **i7-2600, 8 ГБ RAM и GTX 1050 Ti 4 ГБ** в нативном режиме начните с буфера **80 мс**. На новом ПК он выбран по умолчанию; после обновления выберите его вручную, остановив микрофон. SDK работает на CPU; выбор ускорения скрыт. После остановки микрофона сбрасывается аудиопоток, а общие модели остаются в памяти до закрытия приложения: SDK не поддержал повторное создание уничтоженного экземпляра. Профиль голоса переключается без перезагрузки общей модели.

Ориентируйтесь на устойчивый звук и счётчик потерь: SDK работает пакетами, поэтому отдельный вызов может занимать дольше короткого блока. Полная задержка включает захват, обработку, воспроизведение и виртуальный кабель. Для меньшей задержки при устойчивом звуке попробуйте 40 мс. При прерываниях увеличьте значение до 160 мс, затем при необходимости до 320/480/640 мс. Замеры Windows CI не заменяют испытания на вашем компьютере.

В нативном режиме размер аудиопорций выбирает драйвер. Входные порции собираются в выбранный блок AI, а выход передаётся в виртуальный кабель и наушники частями без потери остатка. Это убирает дополнительное ожидание большого блока на стороне захвата и воспроизведения. Очереди ограничены с учётом пакетной работы SDK, чтобы короткие блоки не терялись при резком скачке времени обработки. Физическую задержку устройств и внутреннюю задержку SDK эта настройка не устраняет.

В списках устройств выбирайте WASAPI. Для G435 предпочтителен USB-приёмник LIGHTSPEED: Bluetooth может добавлять заметную задержку. В Windows установите 48 кГц у микрофона, виртуального кабеля и наушников, если устройства поддерживают эту частоту. Ручной сдвиг высоты добавляет задержку отдельного эффекта; для минимальной задержки оставьте его на нуле.

Прежний RVC-режим использует отдельную модель голоса, ContentVec, определение высоты и SOLA. В нём доступны CPU/DirectML и лёгкий/полный профили; начальный буфер — 320 мс. Эти настройки не относятся к нативному SDK.

Язык, темп и интонации в основном следуют вашей речи. Чтобы получить нужную русскую озвучку персонажа, нужна подходящая модель или профиль. Манера актёра не добавляется автоматически.

При загрузке показывается статус; исходный микрофон не подставляется вместо AI при ошибке. Настройки эффектов и нативный профиль можно менять во время работы. Для смены RVC-модели, ускорителя, режима или буфера сначала остановите микрофон.

Кнопка **«Добавить AI-голос…»** импортирует RVC ONNX из файла или HTTPS-ссылки Hugging Face. Общие модели из установленного приложения используются повторно. При их отсутствии они скачиваются с проверкой SHA256. Файлы `.pth` требуется заранее экспортировать в поддерживаемый ONNX; приложение не исполняет Python-чекпойнты. Пользовательские модели хранятся в `%APPDATA%\VoiceLab\models`, установленные вместе с приложением — в его папке `models`. Удаление приложения сохраняет импортированные пользователем голоса и настройки.

## Запуск исходников для разработчика

Установите [Python 3.12 x64](https://www.python.org/downloads/windows/) с Python Launcher (`py`), скачайте и распакуйте проект, затем откройте `Start-VoiceLab.bat`. При первом запуске зависимости устанавливаются автоматически. Для восстановления зависимостей выполните в папке проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\setup-windows.ps1
```

Если установлен `py`, скрипт использует Python 3.12. Без `py` поддерживается команда `python` версии 3.11–3.13, x64. Рекомендуемый и целевой вариант сборки — Python 3.12 x64.

## Виртуальное устройство Windows

Виртуальный аудиокабель устанавливается из мастера npetrov VoiceLab либо кнопкой в приложении. Это официальный драйвер VB-CABLE; само приложение не заменяет системный аудиодрайвер.

1. Если VB-CABLE ещё не установлен, используйте кнопку установки в npetrov VoiceLab. Альтернативный ручной вариант — [официальный сайт](https://vb-audio.com/Cable/). После установки перезагрузите Windows, если этого потребует драйвер.
2. В VoiceLab оставьте режим **«Виртуальный микрофон»** и выберите ваш физический микрофон. Приложение автоматически найдёт **CABLE Input (VB-Audio Virtual Cable)**. Основной выход этого режима — виртуальный кабель; галочка прослушивания дополнительно направляет тот же обработанный звук в наушники. Если кабель не обнаружен, запуск блокируется и показывается кнопка установки.
3. В **Параметры Windows → Система → Звук → Ввод** появится **CABLE Output (VB-Audio Virtual Cable)**. Выберите его в списке микрофонов нужной программы или игры. Устройство создаёт драйвер VB-CABLE; отдельная интеграция с Discord не требуется.
4. Устройство **вывода** Windows и принимающей программы оставьте на наушниках. Нажмите «Включить микрофон» в npetrov VoiceLab.
5. Если Discord срезает эффекты, попробуйте отключить Krisp/шумоподавление, эхоподавление и автоматическое усиление. Входную чувствительность настройте вручную.

Маршрут: **микрофон → npetrov VoiceLab → CABLE Input → CABLE Output → Discord/игра**.

Виртуальный CABLE Output скрыт из списка микрофонов npetrov VoiceLab, чтобы не создавать звуковую петлю. Основные устройства и режим можно изменить после остановки микрофона. Прослушивание переключается галочкой без остановки; для выбора других наушников сначала снимите галочку. Обновите список после подключения нового устройства. Устройства должны поддерживать общую частоту 48 кГц либо 44,1 кГц; движок проверяет оба варианта.

## Прослушивание своего голоса

Выберите выход на наушники под галочкой **«Слышать себя в реальном времени»**, включите микрофон и отметьте галочку. Вы слышите обработанный голос с текущим пресетом и настройками. Отключение галочки или отсоединение наушников не останавливает основной виртуальный выход и запись WAV. При подключении новых наушников остановите микрофон и нажмите «Обновить устройства».

Выбор наушников сохраняется, а сама галочка при запуске приложения выключена. Используйте наушники вместо колонок, чтобы избежать звуковой петли. Задержка зависит от эффектов и аудиодрайвера; это не прослушивание с нулевой задержкой.

В режиме **«Только наушники — без драйвера»** галочка работает так же; VB-CABLE и другие программы не нужны. Для появления отдельного устройства в списке микрофонов Windows нужен режим **«Виртуальный микрофон»** и установленный драйвер VB-CABLE. Устройство называется **CABLE Output (VB-Audio Virtual Cable)**; это и есть вход для других приложений.

Название приложения и ярлыков — **npetrov VoiceLab**. Установщик обновляет предыдущую версию с сохранением настроек; технические имена EXE и папки настроек `VoiceLab` сохранены для совместимости.

## Русская речь и настройка голосов

Обработка работает со звучащей речью на любом языке и не переводит текст. Профиль **«Русская речь»** добавляет фильтрацию низкочастотного шума, мягкую компрессию и регулируемое выделение диапазона согласных около 2,6 кГц. Это помогает разборчивости, но не является языковой моделью или коррекцией акцента.

- **Высота голоса:** от −12 до +12 полутонов без изменения темпа. Экстремальные настройки дают более искусственный звук.
- **Тембр:** эквализация от яркого к тёплому. Это не независимое нейросетевое преобразование формант.
- **Разборчивость речи:** 0–6 дБ усиления присутствия, когда включён речевой профиль. Если шипящие резкие, уменьшите значение.
- **Пространство:** реверберация. Для разговоров начните с 0–15%.
- **Усиление:** настройте так, чтобы выходной индикатор редко достигал максимума. Выход ограничен диапазоном −1…1.
- **Отключить эффекты:** передача исходного голоса по тому же маршруту.

Сохраняются выбранный пресет, устройства и ручные настройки. При выборе нового пресета ручные настройки заменяются его параметрами. Переключение высоты/пресета заново запускает буфер эффекта и может дать короткую паузу. Обработка не имеет нулевой задержки: обычное изменение высоты добавляет примерно 60–100 мс (в новых мультяшных стилях используется короткий алгоритм с историей 1–25 мс) при 48 кГц, кроме буферов устройств и виртуального кабеля. Фактическая задержка зависит от Windows и аудиодрайвера.

## Запись и обработка файлов

«Записать голос в WAV» сохраняет обработанный сигнал, пока включён микрофон. После остановки записи или микрофона WAV-файл закрывается. Сохраняйте запись под новым именем: приложение не перезаписывает существующие файлы.

«Обработать файл» применяет выбранный AI-голос или эффекты к записи без микрофона. Для обработки файла в AI-режиме сначала остановите микрофон, чтобы освободить видеопамять. Выход — моно WAV PCM16 с исходной частотой; в режиме эффектов при активной обработке добавляется секунда для буфера эффекта и хвоста реверберации. Поддержка входных форматов зависит от libsndfile; WAV/FLAC подходят для проверки.

То же из командной строки:

```powershell
.venv\Scripts\python.exe -m voicelab --list-devices
.venv\Scripts\python.exe -m voicelab --render input.wav output.wav --preset sakura
```

## Сборка приложения без Python на целевом компьютере

Разработчику нужны Python 3.12 x64 и [Inno Setup 6 или 7](https://jrsoftware.org/isdl.php). На Windows дважды нажмите **`Build-Windows.bat`**. Скрипт устанавливает зафиксированные зависимости, запускает тесты, собирает AI-движок и интерфейс через PyInstaller и создаёт **один файл `dist\installer\VoiceLab-Setup.exe`**. Только этот EXE передаётся пользователю. Он включает Python, Qt, ONNX Runtime, обработчик звука и мастер скачивания/установки виртуального микрофона. Для включения подготовленного нативного набора используйте `-IncludeNativeSDK`; для прежнего подготовленного RVC-набора — `-IncludeNeuralVoices`. Без этих наборов доступны импорт ONNX и эффекты. Личная Windows-сборка получает SDK из приложенного владельцем установщика, проверяет его SHA256 и не устанавливает чужой аудиодрайвер. Рядом создаётся SHA256-файл для проверки загрузки.

Мастер VB-CABLE включается отдельно параметром `scripts/build-windows.ps1 -EnableVBCableIntegration`. Для личной сборки владельца в workflow этого приватного репозитория включён личный режим; в публичных репозиториях и других форках он не действует. Без включения этого режима устанавливается только приложение, а кнопка виртуального микрофона открывает официальный сайт драйвера. Перед распространением комбинированного установщика другим людям необходимо согласие автора VB-CABLE: это прямо указано в `readme.txt` официального пакета. Файлы драйвера в npetrov VoiceLab не копируются; мастер получает исходный пакет с сайта производителя и проверяет действительную цифровую подпись.

В `.github/workflows/windows.yml` есть Windows CI: тесты, проверка загрузки и подписи VB-CABLE без установки драйвера на runner, сборка установщика, установка в тестовую папку, обработка WAV установленным EXE и удаление. Артефакт — `VoiceLab-Setup-Windows-x64`. Push тега `v*` создаёт GitHub Release с установщиком и SHA256 **только после прохождения всех этих проверок**. Прямой тест драйвера: `powershell -NoProfile -ExecutionPolicy Bypass -File installer\Install-VirtualMicrophone.ps1 -VerifyOnly`.

## Разработка и проверка

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\setup-windows.ps1
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m voicelab
```

Если используется `uv`: `uv sync --frozen --extra dev`, затем `uv run --frozen --extra dev python -m pytest -q`. На Linux дополнительно нужна системная библиотека PortAudio (`libportaudio2`); для проверки интерфейса без дисплея задайте `QT_QPA_PLATFORM=offscreen`. Инструкция для этой облачной среды находится в [docs/VALIDATION.md](docs/VALIDATION.md).

Тесты проверяют каждый из 60 пресетов на потоке блоков, реальное изменение частоты, модуляцию, речевую эквализацию, WAV, защиту от перезаписи, передачу обработанного сигнала между аудиоколбэками с имитацией устройств, освобождение ресурсов при ошибке, поиск и настройки интерфейса.

Отсутствие звука: проверьте разрешение доступа к микрофону для классических приложений Windows, выбранный вход/выход, уровень записи и отсутствие эксклюзивного захвата другим приложением. Если счётчик потерь буфера постоянно растёт, закройте тяжёлые программы или выберите другой вариант того же устройства с другим API. WASAPI обычно предпочтительнее MME, но совместимость зависит от драйвера.

Зависимости: PySide6 Essentials (Qt), NumPy, Pedalboard, sounddevice/PortAudio, SoundFile/libsndfile. Их лицензии и уведомления следует сохранять при распространении собранного приложения.

## Подготовка личного набора моделей

Тег релиза в этом приватном репозитории запускает подготовку шести моделей: выбранные `.pth` извлекаются HTTP Range-запросами из зафиксированной версии архива; целиком архив 39 ГБ не скачивается. В изолированной среде PyTorch CPU загружает только веса, экспортирует энкодер и декодер в ONNX и проверяет разные длины блоков. ContentVec/RMVPE скачиваются по зафиксированным версиям с проверкой SHA256. Каждая модель проходит преобразование настоящего речевого WAV на CPU. Происхождение, исходные хеши и версии сохраняются в `SOURCES.json`.

Экспортные зависимости зафиксированы с хешами в `scripts/neural-build-requirements.lock` и устанавливаются в `.neural-build`. Они не попадают в PyInstaller. Скрипт `scripts/prepare-neural-voices.py` создаёт `dist/neural-models`; Inno Setup включает эту папку в личный установщик и устанавливает её в `{app}\models`. Затем CI проверяет преобразование WAV установленным EXE для каждого из шести голосов. Отдельный workflow `Validate offline neural voices` позволяет проверить подготовку 1–6 моделей до релиза.

Большой личный установщик можно собрать и опубликовать через ручной запуск workflow `Windows app` с `publish_release=true`. Тег создаётся после успешных проверок; EXE и SHA256 загружаются непосредственно в черновик релиза, затем релиз публикуется. Это избегает дополнительного хранения большого установщика в Actions Artifacts. Опубликованная версия повторно не перезаписывается; существующий тег должен указывать на собранный коммит. `include_native_sdk=true` включает личный нативный набор (при публикации он включается автоматически); `include_neural_models=true` дополнительно готовит прежние шесть RVC-моделей.
